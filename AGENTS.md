# Workspace Rules & Instructions

## 🚨 Mandatory Rule: Always Consult and Apply Local Skills First

Before undertaking **ANY** action, task, implementation, debugging, refactoring, code review, optimization, or git operation in this repository, you **MUST**:

1. **Inspect and Use Local Skills Directory (`./skills/`):**
   Prioritize the specialized skills provided in the local `skills/` folder. Always load and apply the appropriate `SKILL.md` guidelines for the domain of the task:
   - **Bugs, Failures & Runtime Errors:**  
     Use `skills/debugging-and-error-recovery/SKILL.md` (Stop-the-line rule, reproduce, localize, fix root cause).
   - **Code Changes, Quality Gates & Reviews:**  
     Use `skills/code-review-and-quality/SKILL.md` (Five-axis review: correctness, readability, architecture, security, performance).
   - **Performance, Latency & Timeouts:**  
     Use `skills/performance-optimization/SKILL.md` (Measure before optimizing, identify actual bottlenecks).
   - **UI, Components & Accessibility:**  
     Use `skills/frontend-ui-engineering/SKILL.md` (Component architecture, composition, accessibility).
   - **APIs, Routes & Contracts:**  
     Use `skills/api-and-interface-design/SKILL.md` (Contract first, consistent error semantics).
   - **Git Operations & Commits:**  
     Use `skills/git-workflow-and-versioning/SKILL.md` (Atomic commits, descriptive messages, verify clean build before push).
   - **Task Planning & Breakdowns:**  
     Use `skills/planning-and-task-breakdown/SKILL.md` (Vertical slices, verifiable acceptance criteria).
   - **CI/CD & Automation:**  
     Use `skills/ci-cd-and-automation/SKILL.md` (Quality gate pipelines, automated checks).

2. **Execution Protocol:**
   - Do **NOT** bypass local skills or improvise solutions without consulting the relevant skill guidelines.
   - Formulate actions, verifications, and explanations based on the methodologies defined in these skills.
